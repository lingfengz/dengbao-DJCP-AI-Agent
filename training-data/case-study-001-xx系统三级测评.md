# 测评案例 #001：xx系统 三级等保测评

> **版本说明（2026-08-13）**：本案例为 2025 年度测评记录。"上次得分 71.74" 为上一测评周期按 2021 版报告模板得分制数据；2025 版模板起取消打分制，改用"符合率 + 重大风险隐患"判定（符合 = 符合率>90% 且无重大风险隐患）。案例中的四层交叉验证方法论不受影响。

> **案例说明**：本案例记录了一个真实的第三级（S3A3）系统的完整等保测评过程，涵盖附录A（资产清单）、附录B（上次整改）、附录C（汇总计数）、附录D（详细记录）的四层数据交叉验证与问题分析。  
> **用途**：作为训练数据喂给等保 DJCP AI Agent，使其掌握：
> 1. 真实测评报告的阅读与分析能力
> 2. 四层数据交叉验证的方法论
> 3. 整改追踪与问题归类的标准流程
> 4. 从测评数据中提炼系统性风险的思维模式

### 云平台侧设备的大坑

> ⚠️ 云平台提供的8类安全设备（网络入侵防护、云堡垒机、日志审计、漏洞扫描、主机安全服务、数据库审计、态势感知、VPN）**不作为测评对象**。  
> 这意味着：虽然云平台有这些能力，但租户侧**没有管理权限**，部分测评项（如边界防护c-非授权外联、恶意代码防范b-垃圾邮件）标记为**不适用**。

**对 AI Agent 的训练启示**：要能区分"云平台负责"和"租户负责"的边界，不能因为云平台有某能力就判定租户侧该项为符合。

## Part 6：系统性P0风险（跨层）

本案例共识别出 **5个跨层P0级系统性风险**：

### P0-1：用户登录无多因素认证

| 维度 | 详情 |
|------|------|
| 影响范围 | 服务器×4 + 终端×4 + 数据库×2 + 应用系统×6 |
| 风险 | 攻击者窃取单一口令即可获得系统全部或部分访问权限 |
| GB/T 22239要求 | 三级系统应"采用两种或两种以上组合的鉴别技术" |
| 行业普遍性 | 2025年三级系统仍无双因素极为常见，属于高发性风险 |

### P0-2：管理员权限无制约（无三权分离）

| 维度 | 详情 |
|------|------|
| 影响范围 | 服务器×4 + 数据库×2 + 应用系统×6 |
| 风险 | 系统管理员可一人完成所有操作，无操作审批、无独立审计 |
| 整改建议 | 创建安全管理员+审计管理员独立账户，配置sudo策略和日志审计 |

### P0-3：存储数据完整性无保护

| 维度 | 详情 |
|------|------|
| 影响范围 | 所有系统的全部数据（鉴别数据/配置数据/业务数据/审计数据） |
| 风险 | 数据库被篡改后无法检测；后续法律纠纷无技术证据 |
| GB/T 22239要求 | 三级系统应采用密码技术保证存储数据的完整性 |

### P0-4：无异地灾备 + 从未做恢复测试

| 维度 | 详情 |
|------|------|
| 影响范围 | 所有系统 |
| 风险 | 本地机房灾难（火灾/电力/硬故障）将导致数据完全丢失；备份可用性从未验证 |
| 整改建议 | 异地备份是三级系统刚性要求，恢复测试是验证备份可用性的唯一手段 |

### P0-5：外包开发无安全审查

| 维度 | 详情 |
|------|------|
| 影响范围 | 全部6个应用系统（均为第三方开发） |
| 风险 | 交付物可能含恶意代码或高危后门；未经安全测试直接上线 |
| GB/T 22239要求 | 三级系统应对外包开发代码进行安全审查和白盒测试 |

## Part 7：整改建议（按优先级）

### 🚀 第一梯队（1-2周，技术快速修复）

1. 配置**口令复杂度策略**（服务器: /etc/pam.d/system-auth + /etc/login.defs; 数据库: validate_password插件）
2. 启用**登录失败锁定**（服务器: pam_faillock; 数据库: CONNECTION_CONTROL插件）
3. 开启 **SELinux**（Disabled → Enforcing）
4. 限制**管理终端IP白名单**
5. 应用系统配置**会话超时**和登录失败锁
6. 执行一次**恢复测试**（所有系统）
7. 补做**巡检报告**（至少12个月）

### 🏗️ 第二梯队（1-3个月）

1. 部署**双因素认证**（RADIUS/Google Authenticator/硬件Token）
2. 实现**三权分离**账户体系
3. 数据存储加 **HMAC** 或签名
4. 制定+实施**异地备份方案**
5. 补做 **恶意代码检测** + **代码安全审计**
6. 建立**配置信息库**

### 🔭 第三梯队（3-6个月）

1. 采购 **WAF** 实现应用协议级过滤
2. VPN网关更换**商密认证产品**
3. 实现**可信验证**（可信启动/度量）
4. 建立**服务商评审机制**
5. 建立**全面安全检查制度**

## Part 8：AI Agent 学习要点总结

### 本案例示范的能力

1. **四层数据交叉验证** — 如何用A检验B、B对比D、C核查D
2. **整改追踪** — 不是看这次过了多少个，而是看上次列出的问题改了没有
3. **系统性风险提取** — 从几百项测评数据中提炼出5个跨层P0风险
4. **云租户边界识别** — 区分云平台负责 vs 租户负责
5. **整改优先级排序** — 技术可快速修复 vs 需长期建设

### 常见陷阱提醒

- ❌ 看到"入侵防范c"（有态势感知+抗APT）→ 判定为符合✅（不是不符合）
- ❌ 看到"边界防护c"（非授权外联）→ 判定为不适用（云平台负责），不是不符合
- ❌ 看到"上次测评过了很多项" → 要核查整改清单，可能85%都没改
- ❌ 看到"云平台有安全设备" → 不代表租户侧该项为符合（可能无管理权）
- ✅ 服务器身份鉴别a（有唯一标识+无复杂度）→ 部分符合⚠️，不是不符合
